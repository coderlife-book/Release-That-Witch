# 《放开那个女巫》3D 关系图谱设计

## 目标

把原来的单文件人物关系页升级为可长期维护的知识图谱项目。图谱同时表达人物、组织、地点、王国和抽象体系，核心仍以罗兰为主要浏览入口。

## 剧透边界

当前边界固定为：**温蒂测试飞行设备（滑翔之翼）**。

数据只能包含此进度之前已经明确的信息；不得写入此后的身份揭示、人物结局、势力变化、战争结果或伏笔回收。对当前进度刚进入视野但信息尚未完全公开的节点，使用中性描述。

## 信息架构

节点分为五类：

- `person`：人物
- `organization`：组织与机构
- `location`：地点与区域
- `kingdom`：国家
- `concept`：用于聚合的体系节点，例如“四大王国”

第一版必须包含：罗兰核心人物、女巫联盟、市政厅、第一军、沉睡岛女巫、第三边陲区、温布顿王室、四大王国、教会、审判军、神罚军、赫尔梅斯。

## 关系模型

关系支持：核心关系、成员、领导、治理/管辖、驻地/位于、家族、协作/支援、军事、合作/同盟、敌对、隶属/组成、相关线索。

每条关系只描述当前进度已经成立的事实，不记录未来状态。

## 交互

- 拖拽旋转、滚轮缩放
- Hover 高亮节点及一跳关系
- 点击锁定节点，并在详情栏查看直接关系
- 详情中的关系可以反向聚焦到另一节点
- 支持节点类型、阵营/体系、文本搜索、仅看罗兰直接关系
- 双击场景或按钮可回到罗兰

## 视觉编码

- 人物：球体
- 组织：八面体
- 地点：环形节点
- 王国：多面体
- 体系：核心多面体

颜色用于表达阵营/组织体系，而不是人物善恶。

## 工程结构

- `src/data.ts`：唯一事实数据源与类型定义
- `src/GraphScene.ts`：Three.js 渲染、布局、拾取、高亮和相机
- `src/main.ts`：筛选、详情面板、页面状态
- `src/styles.css`：响应式 UI
- `tests/data.test.ts`：图谱引用完整性、关键节点和剧透边界测试

数据层必须和 Three.js 场景解耦，以便后续阅读进度更新时只修改数据。
